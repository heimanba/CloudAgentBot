# 实施方案

## 适用场景

某个功能、修复、迁移或重构跨越多个文件、层次或负责人。

## 流程

1. 复述用户可见的结果与验收标准。
2. 检查相关代码路径、测试、已存储数据与发布约束。
3. 区分必须完成的工作与可选后续项，识别兼容性需求。
4. 把工作拆分为最小的可独立验证步骤。
5. 为每个步骤指定负责人或职能，并指出依赖关系。
6. 定义相称的测试、人工检查、遥测、回滚与文档。

## 产出

提供范围、非目标、假设、有序工作项、责任分工、测试、风险、上线安排与完成标准。

## 边界

在检查现有行为之前不要提出修改方案。保留用户无关的工作成果，破坏性迁移或不可逆的外部操作必须先获得确认。
