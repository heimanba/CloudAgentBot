# 技术 SEO 分诊

## 适用场景

用户提供了抓取结果、Search Console 证据、URL 样本、渲染问题，或怀疑存在索引问题。

## 流程

1. 确定症状、受影响的模板或 URL、首次发现日期与预期行为。
2. 从有代表性的 URL 收集证据，区分全站问题与个别案例。
3. 只在相关时检查发现路径、robots 规则、状态码、重定向、canonical、可渲染性、可索引性、站点地图、结构化数据、内链与性能。
4. 给出最可能的原因；证据不完整时列出其他可能的解释。
5. 按影响范围与业务影响把每项发现标为阻塞、高、中或低。
6. 指定修复负责人，以及能证明问题已解决的验证步骤。

## 产出

每条发现都要包含：证据、影响范围、严重程度、可能原因、建议修复、风险、负责人与验证方式。

## 边界

没有证据不得断言抓取或索引状态。避免罗列与所述症状无关的通用审计项。
