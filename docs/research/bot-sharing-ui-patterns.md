# 助手共享入口与信息层级研究

研究日期：2026-09-29。依据官方产品文档，不代表已登录或实测这些产品的当前界面。本文只借鉴信息组织方式，不迁移外部产品的权限模型。

## 官方产品事实

| 产品 | 官方文档确认的交互 | 来源 |
| --- | --- | --- |
| Notion | 页面顶部使用一个 Share 入口，进入后查看或修改共享对象、权限以及复制链接；General access 位于这个入口内；移除共享对象也在共享菜单内完成。 | [Sharing & permissions](https://www.notion.com/help/sharing-and-permissions) |
| Figma | 文件右上角 Share 打开共享弹窗；范围、角色与链接操作集中在弹窗，点击范围行还能进入进一步设置。 | [Share files and prototypes](https://help.figma.com/hc/en-us/articles/360040531773-Share-files-and-prototypes) |

这些事实支持“简短入口 → 就地呈现细节”的组织方式，但不能证明这些产品完全没有常驻说明，也不直接规定本项目的按钮颜色、行高或布局尺寸。

## 本项目的事实边界

依据 [CONTEXT.md](../../CONTEXT.md)：共享 metadata 仅控制同 Provider、同 API Key 范围的团队发现状态，不创建成员身份，不授予或撤销 Provider 权限。未共享不能表述为“仅自己可见”或“私有”。同一 API Key 范围的任务历史可跨设备看到；共享助手不会额外授予聊天访问权限。接收设备缺少本机管理资料时不能直接编辑配置。

## 设计结论（本项目的推断与建议）

1. 管理页服务于找到助手和执行操作。共享入口保持可见，解释文字在用户操作时出现。页面顶部不再堆叠共享范围、凭据与历史说明。
2. 用「我的助手 / 团队共享」切换发现范围；角色与共享范围不能放入同一组平级切换。页面标题、主操作与工具栏共享稳定的对齐关系。
3. 每行集中展示名称、真实描述、必要状态和操作。去掉空描述兜底、常驻远程 ID 与重复共享标签；复制 ID 等辅助动作可以放到更多菜单。
4. 可管理助手每行只保留一个可见的「共享」或「已共享」按钮。点击都打开同一共享设置层；「已共享」不能一点击就取消。状态和动作不再重复占据两处。
5. 共享设置层使用短标题、状态与一段范围说明。建议正文：“在使用同一服务和 API Key 的设备上显示。共享不改变访问权限，同范围任务历史可跨设备查看。”开启与取消各用明确动作，取消后的解释仅需：“从团队共享中移除，不撤销已有访问权限。”
6. 「团队共享」旁保留按需查看的说明入口；空列表只在需要指引时补充一句“使用同一服务与 API Key 的设备可发现已共享助手”。有结果时不重复教育文案。
7. 不能出现成员头像、邀请框、权限下拉、公开链接或“仅我可见”等暗示尚不存在能力的控件。简化文字不能删除操作前必须知道的共享范围与历史事实。

## 验证重点

- 未共享、已共享、远程可用但不可管理的助手都具有清楚且一致的操作位置。
- 键盘可打开共享设置、读取范围、关闭并回到触发按钮；关键信息不能仅存在于悬停提示。
- 普通列表首屏不重复出现凭据和历史说明；共享设置层仍准确解释两者。
- 开启、取消、失败与处理中状态可区分；取消共享不被描述为撤销权限。
- 在实际运行应用检查管理列表、聊天页共享入口与窄窗口，确认统一入口和文案不会造成新的布局拥挤。
