# 桌面体验改进建议

## 背景与判断

本建议基于 2026-09-23 对当前 Electron 开发版的实际走查，以及 Grok Bot、Qoder 桌面端和 Codex 官方产品资料的对照。走查覆盖 Connection 管理、Chats/Bots 导航、历史 Chat、创建 Bot 表单，以及创建 Chat、发送、收到回复、归档的闭环。当前工作区在一个 Connection 下有数百个 Bot 和近千个 Chat，因此目录规模已经是现实场景。

三个参考产品提供了不同启发：Grok Bot 让工作对象和进展容易辨认；Qoder 将对话、执行记录、任务摘要与产出分层；Codex 让长任务保留清楚的上下文和可审阅结果。CloudAgentBot 的事实权威仍由 Provider 持有，不能将这些产品的持久记忆、任务、工作树或后台能力直接移植进来。

本项目继续遵守 `CONTEXT.md` 和 `docs/architecture.md`：Chats 是日常默认入口，Bots 是管理入口；不新增本地 Chat、Message、Turn 或发送 Operation 持久化，不改变 Bot/Chat 的远程身份，不根据普通文本推断协作路由。所有以下分组、摘要、排序与定位均为可丢弃的 Renderer 派生视图。实施 UI 时遵守本目录 `AGENTS.md` 的 shadcn/ui、Tailwind v4 和设计 token 规则。

## 第一阶段：让 Chat 时间线可读（最高优先级）

### 1. 工作记录折叠为连续片段

**现状**：`chat-detail-page.tsx` 对 `events` 逐项渲染 `TimelineItem`；`timeline-item.tsx` 虽然可折叠单个工具事件，但每条工具调用、结果和 Thread ID 都占一个可见行。长会话中，正文被大量操作行隔开。

**建议**：在 Renderer 增加纯派生时间线模型。连续的 `thinking`、`tool-call`、成功 `tool-result`、普通 `status` 和 `usage` 合为一段工作记录，首行显示「处理了 12 步 · 4 次工具调用」等可验证的计数，展开后按 Provider 原顺序显示全部事件。用户消息、助手消息、产物、明确错误、失败工具结果均为分段边界；不同 `threadId` 不合并。缺少可靠 `threadId` 时只合并相邻事件，不跨消息推测归属。

**默认层级**：用户输入、助手回复、产物和错误为主层；工作记录摘要为次层；原始输入输出、状态与 ID 在展开层。正在运行时可以显示最近可确认的事件类型及经过时间，不用文本生成「正在执行某任务」等 Provider 未声明的事实。

**验收**：用包含 100 条以上工具事件和多个 Thread 的真实历史会话验证：默认视图能连续阅读问答；所有事件在展开层按原顺序可见；搜索和筛选仍能命中折叠内容并定位对应片段；错误无需展开即可发现；刷新后由远程历史重建同一展示。

### 2. 原始 ID 移到详情层

**现状**：Chat 页头持续显示完整 `Session ID`，工作记录每行显示完整 `Thread ID`。这些 ID 对诊断有价值，但会挤压 Bot 和 Chat 标题。

**建议**：页头第一行只显示 Chat 标题，第二行显示所属 Bot 和 Provider；Session ID 留在现有「管理 Chat」菜单中并保留复制。Thread ID 留在展开的事件详情中。无可读远程标题时，展示短格式 `Chat · 9月23日 10:11` 或首条用户消息的截断预览，并在详情中标明实际远程标题和 ID。此处仅为展示兜底，不改写 Provider 标题，也不形成本地身份。

**验收**：长 Bot 名、长 Chat 标题和 640px 窗口下页头不挤掉刷新及菜单；完整 ID 可在两步内复制；无标题 Chat 在侧栏和正文显示一致。

## 第二阶段：提高大目录的定位效率

### 3. 新建 Chat 先展示可选对象，再提供完整搜索

**现状**：`new-chat-panel.tsx` 默认把当前 Connection 下的所有 Bot 直接渲染到选择器。目录大时，用户需在长列表中识别目标。

**建议**：空搜索状态先展示「最近使用的 Bot」（由已加载的远程 Chat roster 派生）和「受管理的 Bot」，再显示其余 Bot；搜索仍覆盖当前 Connection 的完整 Bot 列表，并同时匹配名称与职责描述。重复名称用 Provider 可读信息或 ID 短尾辅助区分，不把短尾当作新身份。目录未加载完时清楚标示进度与搜索范围。

**验收**：百级 Bot 列表中可快速找到最近使用对象；搜索能找到远程 Bot；重复名称不会导致无法判断目标；创建行为仍走现有 `createChat`。

### 4. Chats 首页提供可靠的关注线索

**现状**：`chat-navigation-model.ts` 按远程更新时间取最近 8 个 Chat，全部 Chats 按时间排序。它能恢复最近会话，但无法直接提示哪一条需要回看。

**建议**：仅对 Provider 明确返回的失败、仍在运行或其他可确认状态加轻量状态标记。先在 Chat 行和详情页使用，不新增独立「待办」对象或持久列表。避免仅凭旧 `remoteStatus` 推断当前正在运行；状态不可靠时退回更新时间排序。当前 Connection 的加载进度和部分失败继续可见，避免把不完整 roster 误显示为完整结果。

**验收**：运行、失败、已结束的标记与刷新后的 Provider 事实一致；无法确认状态时不显示误导性标记；跨 Connection 切换后不混入其他账号的状态。

### 5. 长会话增加定位，而非常驻第三栏

**建议**：扩展现有「工作记录」Popover，提供「用户消息」「错误」「产物」「最近回复」的锚点列表，并支持跳转到对应事件。桌面宽屏可以后续评估可选的辅助面板，首批保持当前双栏阅读布局。锚点由当前载入的远程事件派生，事件列表更新时同步重算。

**验收**：数百事件的 Chat 中，键盘和鼠标都能快速定位最近错误或产物；锚点不遮住正文和输入框；窄窗口仍可使用。

## 第三阶段：降低配置的理解成本

### 6. 创建 Bot 的文案与配置层级

**现状**：`bots-page.tsx` 的说明写「设置名称和 Instructions」，实际可见字段是名称与职责描述；编辑页才有独立 Instructions。Skills、MCP、协作成员在创建页同时展开。

**建议**：创建页说明改为与实际字段一致，并说明创建时采用的默认 Instructions。首屏聚焦名称、职责描述和模型；Skills、MCP、协作成员归入可展开的「更多配置」，同时保留已选项摘要。编辑页继续明确区分「给用户看的职责描述」与「给 Bot 的 Instructions」。配置生效范围的说明放在保存动作附近统一展示，避免每个选择器重复一遍。

**验收**：首次创建者能解释每个必填字段的作用；高级配置可发现且选中后在收起状态可见；新建 Chat 才使用新配置的限制在提交前清楚可见。

### 7. Connection 维持前置条件语义

**建议**：保留 Connection 作为凭据和默认 Environment 的设置入口，不把它改成第三个日常工作区。就绪状态、Environment 是否完成、验证错误放在连接卡片的第一层；Workspace ID 和凭据细节留在详情。切换 Connection 后清楚更新 Bot/Chat 数量与加载进度。

**验收**：用户能在连接列表判断哪条连接可用于创建 Chat；凭据失败和运行环境未设置的修复路径可直接到达；不会误以为切换 Connection 后仍在原账号的 Chat 中。

## 第四阶段：视觉与响应式收敛

### 8. 建立稳定的四层信息层级

主层：Chat 标题、消息正文、产物和阻断错误。次层：Bot 身份、运行状态和工作记录摘要。辅助层：时间、Provider 与管理状态。诊断层：Session/Thread ID、工具输入输出、usage 与原始事件类型。主层用现有字号和对比度 token；辅助层不低于项目规定的 caption 可见字号。Bot 头像可帮助扫描，但状态必须同时有文字或可访问名称，不能只依赖颜色或动效。

### 9. 真实窗口尺寸验证

此前一张桌面截图只截取了窗口左侧，不能据此认定弹窗在窄窗口中溢出；当前 `DialogContent` 已有 `100vw` 限制。因此将 1024×700、约 790×650 和 640×600 的真实 Electron 窗口列为验收尺寸，分别检查弹窗、创建表单、时间线、Popover 和输入框是否有横向溢出、双滚动或遮挡。若复现问题，再按实测定位断点。键盘焦点、屏幕阅读器状态提示和 `prefers-reduced-motion` 同步验证。

## 实施批次与依赖

| 批次 | 内容                                         | 可交付结果                     |
| ---- | -------------------------------------------- | ------------------------------ |
| A    | 时间线派生分组、错误露出、ID 层级            | 长会话默认可读，诊断细节可展开 |
| B    | 新建 Chat 选择器、Chats 状态和锚点           | 大目录与长会话可快速定位       |
| C    | 创建 Bot 文案及渐进配置、Connection 状态层级 | 首次创建与连接修复更清楚       |
| D    | 真实窗口和辅助技术验收、视觉 token 收敛      | 三档窗口均可完整操作           |

每批先用真实历史与当前 Provider 视图核对信息是否可靠，再做 UI。修改 Design System Primitive 后按 `AGENTS.md` 执行 typecheck、lint、Primitive 测试和相关 Feature 测试；涉及导航和时间线派生模型时增加针对边界行为的测试，并在 Electron 中复核完整流程。
