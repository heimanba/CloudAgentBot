# Session 协作标识与成员入口实施计划

## 目标

让用户在任务列表和详情中一眼辨认创建时配置了协作成员的 Session，同时保持协调者 Bot 仍是 Chat 唯一归属。成员头像只表示 Session 创建时的远程快照，不表示成员实际参与。

## 已有事实与边界

- `ChatView.collaboration.memberAgentIds` 来自该 Session 的 Provider 快照；缺失、异常或空数组均不展示协作标识。
- 成员名称只从当前 Connection 已加载的 Bot 目录解析。不可见成员保留短 ID，不推断其删除、归档或参与。
- 实际委派只由 Provider Thread 事件证明。本次不改事件模型、Provider 合同、身份或本地存储。
- 列表已显示“协作任务”文字；详情已有默认折叠的成员卡。本次替换其位置与形态，保留展开后的完整信息。

## 设计与实施

1. 新增只读的 Session 头像组合组件。协调者头像始终在前；快照成员显示一枚小头像，余量显示 `+N`，列表和详情页头使用同一规则。“协作任务”文字提供完整语义。无法从当前目录解析的成员显示匿名占位而非伪造名称头像。头像组合整体是装饰性的，语义由相邻文字提供。Provider 角标只附着在协调者头像，不被成员遮盖。
2. 最近任务、搜索结果和全部任务共用 `ChatNavigationRow`：有协作快照时显示头像组合，并保留“协作任务”文字。普通任务保持单头像。窄栏中标题、时间与 Bot 名称仍有截断优先级；头像不挤掉主要文字。
3. 详情页头在协调者身份附近显示紧凑的“协作成员 N 位”入口。点击后由现有 Popover 展示创建时快照的成员列表及“是否参与请看协作过程”说明。移除时间线顶部的成员卡，避免占用首屏。键盘、Escape、焦点归还由既有 Popover Primitive 处理。
4. 只使用现有 Tailwind token、BotAvatar、Popover；不新增 CSS、Primitive、状态持久化或远程调用。

## 验收

- 普通、快照缺失、快照为空：列表与详情无协作头像或入口。
- 快照有 1、2、3 位以上成员：侧栏和详情页头的头像数量与 `+N` 一致；名称只来自同 Connection 当前目录；不可见成员有中性占位。
- Bot 当前 roster 后来改变时，旧 Session 的标识仍按 Session 快照；未有 Thread 证据时不显示“已参与”。
- 详情默认没有占据阅读列的成员卡；打开入口可读全员及说明。
- 1024×700、约 790×650、640×600 的真实窗口中标题、操作、输入区可用；键盘可打开、关闭成员入口。
- 运行 `pnpm typecheck`、`pnpm lint`、相关 Renderer 测试、`pnpm test:arch`；若未改 Primitive，无需额外 Primitive 测试。

## 实施前 Review

- **事实审查：通过。** `CONTEXT.md`、ADR-0009、架构文档均要求以 Session 快照标识历史协作，不能从当前 Bot 配置推断实际参与。
- **组件审查：通过。** 列表共用一个 `ChatNavigationRow`；详情已有 Popover。无需改 Main、Provider 或 Design System Primitive。
- **风险审查：需处理。** 当前目录可能缺成员或出现同名成员，故头像只在 ID 匹配时显示当前名称；不可见成员使用匿名占位。窄栏可能拥挤，列表和详情统一只显示一枚成员头像与余量。
- **工作树审查：需保留。** `collaboration-members.tsx` 与协作开发计划已有未提交改动；实施只作局部修改，不回滚既有工作。

Review 结论：范围明确，可进入实施。

## 现场复核调整

开发版实测发现侧栏同时叠放两枚成员头像和 `+N` 会过度挤压标题，因此改为协调者加一枚成员头像和余量；详情页头沿用同一组合。这个调整保留协作辨识度，也使 Chat 标题仍是列表的主信息。

## 实施后 Review 与验证

- 检查代码依赖后，变更只涉及 Renderer 展示和一个 `BotAvatar` 尺寸选项；未增加远程请求、持久化、Provider 语义或新 Primitive。工作树原有协作代码和验证记录改动均保留。
- 对目标 `新 Chat · 9月24日 15:55` 在运行中的 Electron 开发版实测：桌面宽度下侧栏标题、Bot 名与协作标记可读；详情首屏不再出现成员大卡；成员弹层展示三位当前名称及快照说明，Escape 关闭后焦点回到入口。
- 约 790×640 与 640×550 的窗口实测：详情标题、成员入口、刷新/管理/工作记录/定位操作和底部输入框可用；640 宽成员弹层没有溢出。790 宽时副行 Bot 名会按设计截断，主标题完整。
- `pnpm typecheck`、`pnpm lint`、`pnpm test src/renderer`（29 文件、218 测试）、`pnpm test:arch`、`pnpm build`、`git diff --check` 通过。新增测试覆盖 Session 快照与当前 Connection 名称解析，以及列表可访问名称。
- 未做 Provider mutation 或新增 Cloud 资源；此次只读页面验收已覆盖实际目标 Session。

## 左侧标题与悬停详情补充

用户复核指出侧栏较长 Chat 标题仍会被截断。列表标题调整为最多两行；鼠标悬停或键盘聚焦任务行时，现有 Tooltip 显示完整标题、所属 Bot，以及该 Session 创建时的成员人数和当前可解析名称。Tooltip 在整行触发，悬停头像也能看到。列表不把成员名单解释为实际参与；触屏设备仍通过打开 Chat 后的页头入口查看完整名单。

开发版现场复核确认：较长标题可占两行；从侧栏搜索框按 Tab 聚焦目标 Chat 后，Tooltip 显示完整标题、Bot 与三名快照成员。`pnpm typecheck`、`pnpm lint`、相关列表测试与 `git diff --check` 再次通过。

## 头像组合一致性修订

用户截图指出同一 Chat 的侧栏和详情页头头像组合数量不同。两处改为共用同一规则：协调者头像、一名成员头像、`+N`（其余成员人数）；Provider 角标均附着在协调者头像。侧栏继续以两行标题和完整 Tooltip 弥补头像占用的空间。列表、移动端导航、全部任务和详情均只消费当前 Connection 与该 Session 快照。

目标 Chat 的展示标题已包含更新时间，侧栏不再在右侧重复显示同一时间，以保留标题宽度。远程自带的有意义标题仍保留右侧更新时间。开发版复查两处均显示相同头像组合与 Provider 角标，目标侧栏标题完整显示；Renderer 218 项测试、typecheck、lint 和 diff 检查通过。

## Bot 详情入口补充

详情页头的协调者和首位成员头像可直接打开对应 Bot 详情；`+N` 打开完整成员弹层，弹层中的协调者与每位当前目录可解析的成员也可打开 Bot 详情。只在同一 Connection 内按 Agent ID 匹配，避免同名或跨 Connection 误导航；快照成员当前不可见时保留短 ID 且不提供失效入口。侧栏组合仍是整个 Chat 的导航入口，不在其内部嵌套 Bot 按钮。成员列表的点击区域高度为 44px。

在目标 Chat 的 Electron 开发版现场复核：`+2` 打开完整成员列表，点击 EngineeringPixel 成员后进入 EngineeringPixel Bot 详情。组件交互测试覆盖协调者、可解析成员、余量入口；`pnpm typecheck`、`pnpm lint`、Renderer 219 项测试、`pnpm test:arch` 与 `git diff --check` 均通过。

## 跳转可发现性与组件一致性复核

侧栏和详情页头已共用 `SessionCollaborationAvatars`，头像顺序、尺寸、叠放与余量计数来自同一实现。侧栏的整个 Chat 行是一个按钮，点击头像区域打开 Chat；详情页头单个头像才是 Bot 导航按钮，不能在侧栏按钮中嵌套第二层按钮。为明确页头的跳转能力，头像按钮有手型、悬停透明度反馈与焦点描边，悬停/聚焦提示明确写“查看…的 Bot 详情”；标题下的 Bot 名称也变为带外链方向图标的文字入口。成员弹层各行明确显示“Bot 详情 ↗”。不可见成员仍不产生失效链接。

用户截图与开发版实测显示，头像叠放时再放大并画悬停外圈会相互挤压；已去掉放大和悬停外圈，改为不改变尺寸的透明度反馈，键盘聚焦仍保留描边。Tooltip 固定在头像上方。实际 Electron 开发版再次确认：左侧与页头的头像顺序、Provider 角标和 `+2` 一致；打开 `+2` 后能看到协调者及三位成员的“Bot 详情”入口；点击 EngineeringPixel 进入其 Bot 页面，再返回任务可重新打开原 Chat。最终 `pnpm typecheck`、`pnpm lint`、Renderer 219 项测试、`pnpm test:arch` 和 `git diff --check` 通过。

用户进一步明确要放大镜式悬停：放大的头像应浮在其他头像前面。页头三个可操作头像增加独立定位层级，悬停或键盘聚焦时缩放至 125% 并升到最高层级，静态叠放顺序与侧栏保持一致。Electron 开发版分别实测 EngineeringAda 和 EngineeringLin 的悬停：两者放大时均位于其他头像前方，标题及其余头像未发生布局移动。再次通过 typecheck、lint、Renderer 219 项测试、架构检查与 diff 检查。
