- 管理页默认我的 Bot，工作区全部及各筛选计数只包含当前 Key 或本机管理/恢复资料对应的助手；只有更多菜单的显式浏览模式展示未分组远程资源。

- 完整 Provider 目录仍用于协作关系解析与任务历史发现；没有修改 Main、远程身份、权限或存储结构。

使用 V2 Electron 开发应用，当前 Bailian 连接具有 58 个未分组远程 Agent、0 个本机管理助手、0 个团队共享助手。

1. 首页：连接只显示 Bailian / 百炼，无“58 位助手”。
2. 新任务：团队共享为空，我的助手为空，未自动展示远程资源。
3. 输入测试草稿，显式浏览 Provider 资源并搜索 general-expert；候选显示未分组且归属解释可见。
4. 选择 Agents/general-expert 后草稿保留，没有自动创建 Session 或发送。
5. 点击发送后创建远程 Session，发送唯一测试标记 `oab-e2e-discovery-20260929-1022`，要求只回复 ACCEPTANCE_OK 且不调用工具。
6. 实际收到 ACCEPTANCE_OK；最近任务出现一条当前 API Key 的任务。
7. 返回新任务，再打开最近任务，消息与响应保持；刷新任务后仍保持。
8. 重新加载 Renderer，等待远程列表返回后任务重新出现；打开后仍看到完整测试消息与 ACCEPTANCE_OK。

## 验收中发现并处理的环境问题

初次 UI 发送返回 conflict，界面提示检查环境。最小 Provider 创建探针使用同 Agent、Environment 和测试 metadata，创建/清理均返回 200。随后对比运行构建发现：旧 dist/main/index.js 仍含禁止百炼创建私有 Session 的旧分支，当前源码已无该分支。退出旧应用后重新执行 pnpm dev，原 UI 流程通过。没有为此修改业务源码；临时诊断脚本已删除。

窗口调整大小后 computer use 的旧绑定偶尔给出未更新的画面或树；重新 getApp 后可见正确窄布局。不能以此前旧画面的右侧裁切作为布局缺陷的确定证据。
