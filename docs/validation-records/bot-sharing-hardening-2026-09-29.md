## 真机方法

通过 computer use 操作真实 Electron 应用及真实百炼、Qoder。维护端使用开发应用；接收端使用独立 userData 的 Electron 客户端，仅具有相同连接和加密凭据，无 Managed Bot 资料。未使用 UI 假数据或替身接口。

两个客户端在同一台 Mac 上，不能等同于两台物理设备。故障注入通过自动化完成，未在用户网络上断网。接收端使用首次通过 gate 的构建；后续仅补充文案、换行与测试，最终完整 gate 再次验证产物。

| 流程 | 百炼 | Qoder |
| --- | --- | --- |
| 创建临时 Bot，维护端开启共享，接收端刷新发现 | 通过 | 通过 |
| 无管理资料的接收端进入任务并发送 | 通过 | 通过 |
| 刷新保留草稿；用途描述随配置更新 | 通过 | 通过 |
| 新任务采用 V2，旧任务保持 V1 | UI 回复及 Session 快照确认 | UI 回复及 Session 快照确认 |
| 取消共享后刷新移出团队范围，已有任务可继续 | 通过 | 通过 |
| 重载后恢复远程历史 | 通过 | 通过 |

Qoder 管理页另验证搜索词和团队范围在刷新后保留，团队数量由 1 变为 0，全部资源仍保留该 Bot；取消共享不被误认为撤权。约 757 逻辑像素的窄窗口下，管理页、新任务描述与刷新入口无明显裁切，随后恢复窗口大小。

确定性指令标记分别为 `OAB_B_V1/V2` 和 `OAB_Q_V1/V2`。读取远程 Agent 配置与各 Session 的 `agent.system` 快照确认实际版本。Qoder 首次询问“configured version marker”时模型拒绝透露内部配置且回复较慢；旧任务随后发送普通问候返回 V1，新任务返回 V2。版本判定同时依据远程快照，不单凭模型回复。
