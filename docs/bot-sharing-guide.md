# 共享助手使用指南

当前共享适用于 Provider 已授权可见的 Bot，不要求维护者与接收方使用相同 API Key。它帮助同事找到可复用的 Bot，不改变 Provider 权限，也不提供员工个人历史隔离。管理员可以按下面的维护者流程配置助手；成员可以使用各自具有相应 Provider 访问权限的 Key；共享不跨越 Provider 的授权边界。

## 维护者：准备并共享

1. 在「管理助手」创建 Bot，填写名称、职责描述和工作指令。描述用于告诉同事适合完成什么任务；工作指令决定 Bot 的行为。
2. 自己完成一次实际任务，确认回复满足用途。
3. 在助手列表或详情点击「共享」，阅读范围说明后选择「开启共享」。同步与目录读回期间等待操作结束。
4. 告诉同事使用哪个已配置的连接和助手名称。凭据通过团队既有安全流程配置，不把 Key 放进 Bot 描述、工作指令或普通分享消息。

## 接收方：发现并使用

1. 在对应连接打开「新任务」，点击「刷新助手列表」。管理员刚添加或更新助手时也用这个入口刷新。
2. 打开助手选择器，默认范围是「团队共享」。查看描述，选择合适的助手，填写具体任务并发送。
3. 也可以从「管理助手 → 团队共享」打开 Bot 详情，再点击「开始任务」。未持有本机管理资料的接收方不需要导入配置即可使用。
4. 管理页的刷新位于右上角更多菜单；Bot 详情的「刷新助手和任务」会同时更新助手信息与任务列表。

刷新保留搜索、当前范围和任务草稿。刷新后确认所选助手已不存在或不再属于可用范围时，界面要求重新选择，不会代选其他 Bot。

## 更新、失败与取消共享

- 维护者在配置页保存并同步。接收方刷新后看到新描述，**新建任务使用新配置，已有任务保持创建时的配置**。
- 提示同步失败时，保留输入并按界面指引重试。如果提示「配置已同步，助手列表未更新」，只需刷新目录，不必再次同步。
- 读取目录失败会保留上次结果；刷新成功前共享写操作和新任务发送暂不可用，避免把旧目录当成新事实。
- 取消共享后，接收方刷新即可从团队共享候选中移除该 Bot。其他 Key 的接收方不能再通过应用为它新建任务；已有的当前 Key 任务仍可继续，它不撤销 Provider 已授予的访问权限。
- 同一 API Key 范围的任务历史可跨设备查看，与 Bot 是否开启共享无关。不同 Key 的任务历史不会因 Bot 共享而合并。

## 配置维护边界

本机受管理 Bot 的期望配置来自本机 IaC 资料；Provider 保存实际运行资源与任务历史。在 Provider Console 修改同一个 Bot，不会自动合并回本机期望配置，后续同步可能覆盖这些修改。日常配置更新请沿用持有完整管理资料的客户端。

接收方的 Console 配置入口只打开 Provider 管理页面，不表示本机已接管配置，也不额外授予 Provider 权限。
