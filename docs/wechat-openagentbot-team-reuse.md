# CloudAgentBot：共享 AI 助手，用模板组织团队协作

一个会议纪要助手调好了，同事也想用，往往还要重新配置提示词、工具和技能。已经开始的工作需要交接时，又得把材料和上下文解释一遍。

把常用要求留在助手配置里，再把助手或具体任务共享给同事，是 CloudAgentBot 想解决的问题。需要多个视角时，还可以用协作模板组织一组助手。

**CloudAgentBot 是一个开源桌面客户端，让团队创建、使用和共享云端 AI 助手。** 调好一个助手后，已有相应云端资源访问权限的同事可以直接复用；需要交接时，也可以单独共享正在处理的任务。

目前支持 [百炼 Managed Agent](https://docs.bailian.console.aliyun.com/zh/model-studio/managed-agents-introduction) 和 [Qoder Cloud Agents](https://docs.qoder.com/cloud-agents/overview)。本文以百炼 Managed Agents为例，展示会议记录整理和工程页面评审两个场景。功能截图取自 2026 年 10 月 11 日的真实客户端运行，材料均为虚构样例；Qoder 的对应界面不在这次演示范围内。

## 把工作要求配置成一个助手

同样是「整理会议记录」，不同团队的要求可能很不一样。有的关注决策依据，有的强调负责人和截止日期，还有的要求区分已确认的结论与待讨论的问题。

这些要求可以写进助手的工作指令：

> 根据会议记录，分别整理决策、待办和待确认事项。待办包含负责人和截止日期；原始记录中没有提供的信息标为「待确认」，不要自行补充。

在 CloudAgentBot 中，可以为助手设置名称、职责描述、工作指令和模型。职责描述帮助同事判断「这个助手适合做什么」，工作指令则明确处理任务时应遵循的规则。

![会议纪要与文字整理助手配置](https://img.alicdn.com/imgextra/i1/O1CN01T1Yqy4qOZJF49oHY_!!6000000000062-0-tps-2048-1536.jpg)

_演示中将名为 Lin 的助手配置为会议纪要与文字整理用途，保存并同步到云端。_

还可以按任务需要选择技能（Skill）和工具。这次演示从百炼技能广场选择了用于精简文字的 stop-slop，并为助手配置官方 MCP 服务 CodeInterpreter 的代码执行工具。工作指令规定要做什么，技能提供可调用的工作方法，工具负责执行具体操作。

保存并同步后，演示中重新打开配置，确认工作指令、技能和工具关联已经保留。

## 用一份材料，看看助手是否好用

助手配置完成后，可以从「新任务」选择它，输入需求并添加材料。执行过程中，CloudAgentBot 展示云端返回的回复、工具调用和工作记录。

在会议记录示例中，助手实际调用了 stop-slop 技能和代码解释器。代码执行返回 3 项待办，其中 2 项缺少截止日期、1 项缺少负责人。

![技能激活与代码解释器执行记录](images/wechat-proof-20261011/10-skill-mcp-run.png)

_工作记录展示技能激活、代码执行和返回统计，便于核对助手实际做了什么。_

随后上传补充记录，助手补齐了接口开发的截止日期和权限核查的负责人；材料仍未提供的截止日期继续保留为「待确认」。

![补充材料后的会议待办结果](https://img.alicdn.com/imgextra/i2/O1CN01MqUo3aMNH8F49oHY_!!6000000003412-0-tps-2048-1536.jpg)

_补充附件后继续整理待办，缺失信息保留为「待确认」。_

判断助手是否适合团队，可以从这些具体结果开始：决策与待办是否分开，负责人和截止日期是否准确，缺失信息是否明确标出，格式是否便于后续使用。

发现问题后，调整工作指令、技能或工具，再用实际任务检查效果。把反复使用的要求留在助手配置里，同事就可以复用这套经过检验的工作方法。

## 调好之后，让同事直接复用

当助手适合预期用途，就可以开启共享。具有相应云端资源访问权限的同事，可以在「团队共享」中找到它，阅读职责描述，选择助手并提交自己的任务。

这次演示在同一台 Mac 上启动了使用独立本地资料的接收客户端，只配置连接，没有导入维护者的助手配置。接收端的「我的助手」为 0，仍能在「团队共享」中找到开启共享的 Ada。两个客户端使用相同的百炼 API Key；这次截图证明了无需复制本机管理资料即可发现共享助手。

团队可以先在产品评审或项目周会中尝试这套整理要求，再根据实际材料检查是否适用。

![助手共享入口与访问范围说明](https://img.alicdn.com/imgextra/i2/O1CN01Tk4ca1otfnH49oHY_!!6000000004522-0-tps-2048-1536.jpg)

_共享入口示例：工程协调助手 Ada 开启共享，供具有相应资源访问权限的同事发现和使用。_

**共享助手不会额外授予云端访问权限，也不会自动共享助手已有的任务历史。** 同事需要先具备对应服务的资源访问权限，再通过 CloudAgentBot 的团队共享入口使用助手。

## 已经开始的工作，也可以交接

复用助手之外，团队还会遇到另一种需求：让同事沿着已有上下文继续处理一项工作。

例如，一位同事已经整理了会议材料，另一位同事需要接着核实待办、补充背景，再形成后续行动清单。这时可以单独共享该任务，让具有对应云端资源访问权限的同事查看已有内容，并继续发送消息。

- **共享助手**：复用同一套配置，各自处理任务。
- **共享任务**：沿着已有上下文，继续同一项工作。

两种共享状态相互独立。团队可以共享常用助手，同时按需选择需要交接的具体任务。

这次在工程页面评审任务开启共享后，接收客户端打开已有任务，继续要求助手引用 Pixel 的两条交互建议。回复从原来的汇总表中提取了内容，续问没有要求重新委派。

![接收客户端沿着已有结果继续追问](images/wechat-proof-20261011/13-receiver-continued.png)

_接收端读取已有汇总并继续提问。这次使用相同 API Key，没有验证不同凭据之间的任务交接。_

## 从模板开始，组织一组协作助手

单个助手适合职责明确的工作。评审一个会议待办页面时，则需要同时考虑数据规则、交互体验和验收场景，可以交给多个助手分别处理。

CloudAgentBot 提供「从协作模板创建」入口，预置工程、营销、跟进和 SEO 等模板。本次实际创建并运行的是工程模板，其余模板只确认了选择入口。

工程模板为 4 个助手准备了职责和工作指令：

| 助手  | 模板职责                     |
| ----- | ---------------------------- |
| Ada   | 界定范围、协调分工、汇总结果 |
| Lin   | 服务与数据边界               |
| Pixel | 交互体验                     |
| Rigel | 验证与发布风险               |

第一次创建时，演示选择新建成员，实际得到 Ada 和 3 位协作成员。

![从工程模板创建协作助手](https://img.alicdn.com/imgextra/i3/O1CN01tiR0faWoR1D49oHY_!!6000000005490-0-tps-2048-1536.jpg)

_创建结果展示协调助手 Ada 和 3 位成员。模板中的职责用于开始配置，后续仍可分别调整。_

**模板也可以引用已有助手。** 第二次创建时，演示将 3 个成员位置切换为「改用现有 Bot」，选择已经创建的 Lin、Pixel 和 Rigel，只新增一个协调助手 Ada。

![工程模板引用已有助手](images/wechat-proof-20261011/14-reuse-members.png)

_3 个成员位置均引用已有助手，无需再创建一套成员。_

创建后，云端返回的成员 ID 与原来的 3 个助手一致；读回检查确认成员的版本和工作指令没有被改写。每个助手继续独立维护，可以作为协作成员被引用。

这里有一个需要留意的细节：演示后续曾把 Lin 改成会议整理助手，再次引用它时，这项配置也被原样保留。**引用已有助手前，应先确认它当前的职责适合任务，模板不会替它恢复预置职责。**

模板提供配置起点。工具、技能和任务要求仍需按实际工作调整，模板目录中的本地 Skill 文件不会自动导入。

## Teams 协作：协调者分工，成员分别处理

这篇文章所说的 Teams 能力，是一个协调助手引用多个协作成员，在云端任务中委派工作。使用时向协调助手提交任务，CloudAgentBot 展示云端返回的成员委派和消息记录。

在第一次创建的工程协作组中，演示让 Ada 安排 Lin、Pixel 和 Rigel，分别给出会议待办页面的数据校验规则、交互建议和验收场景。这项评审在 Lin 改为会议整理用途之前完成。

![工程评审中的成员委派与消息记录](images/wechat-proof-20261011/05-delegation.png)

_工作记录包含协作子任务创建、跨线程消息和等待成员结果。云端事件确认实际创建了 3 个成员子任务。_

三位成员返回建议后，Ada 将内容整理到一张表里。过程中，有成员的完成状态没有附上具体内容，协调者继续追问后才收齐结果。

![工程页面评审的成员建议汇总](https://img.alicdn.com/imgextra/i2/O1CN01cX96zKhuY6J49oHY_!!6000000001567-0-tps-2048-1536.jpg)

_最终汇总涵盖数据规则、交互建议和验收场景，供团队评审；页面尚未因此完成实现或通过测试。_

这个例子展示了从模板创建、实际分工到汇总建议的过程。配置协作成员不保证每次任务都调用所有成员，也不保证建议符合所有业务要求。团队仍需核对结果，再决定哪些建议进入后续工作。

## 从团队的一项日常工作开始

不必一次配置许多助手。可以先选一项明确、重复发生的工作：整理会议记录、分析材料，或评审一份方案。

把要求写清楚，配置一个助手，用实际材料检查结果。确认好用后，让同事复用；需要交接时共享任务，需要分工时从模板创建或引用已有成员。

这几种复用各有用途：助手配置保留常用工作要求，任务共享保留已经展开的上下文，协作模板减少组织成员与职责的重复配置。

**让一个人调好的助手成为同事可以直接使用的工具，是团队积累 AI 使用经验的一个起点。**

CloudAgentBot 将配置、使用和共享放进同一个桌面入口，任务执行与历史由云端服务管理。百炼 Managed Agent 与 Qoder Cloud Agents 的工具、配置和访问要求有所不同，可以按实际需求选择。

## 体验与反馈

CloudAgentBot 采用 Apache License 2.0 许可证，目前处于早期开发阶段，通过源码启动，尚未提供已签名的正式发行安装包。现阶段更适合愿意自行启动应用的开发者和技术团队体验。

macOS Apple Silicon 已完成本地验收，其他平台的验证状态与启动步骤见仓库说明。使用前需要准备相应云端服务的账号与访问权限：百炼需要国内站北京地域的 AgentStudio 资源权限；Qoder 需要可访问 Cloud Agents 的账号与个人访问令牌。
